# V2_05. Zone 3 (Execution) - 초고속 실행 엔진

Z3는 Z2가 만들어둔 '함정(Plan)'에 조건이 부합하는 순간을 실시간으로 감시하고, 실제 바이낸스 API를 호출하여 자금을 투입하는 기계적이고 빠른 영역입니다.

## 1. Rule Engine (조건 검사기)
*   **주기**: 매 1초 (1000ms)
*   **역할**: `RingBuffer`에서 0.001초 단위로 업데이트 되는 최신 가격, 거래량 볼륨 서지(Volume Surge), CVD 방향 등을 스냅샷으로 가져옵니다.
*   **평가(`ConditionEvaluator`)**: DB에서 불러와 캐싱해둔 활성 `execution_plan`의 `entry_conditions` 로직과 현재 시장 데이터를 대조합니다. 모든 AND/OR 조건이 만족되면 **시그널(Signal)**을 방출합니다.

## 2. Executor (주문 실행 및 관리)
룰 엔진에서 시그널이 넘어오면 지체 없이 주문을 실행합니다.

*   **Risk Gate 검증**: 잔고가 충분한지, 일일 최대 손실(Daily Loss) 한도를 넘지 않았는지, 동시 진입 개수를 초과하지 않았는지 안전성을 검증합니다.
*   **Race Condition 방지**: 비동기 API 호출 중 동일 코인 시그널이 또 들어와 중복 진입되는 것을 막기 위해 `_pendingSymbols` Set(락)을 사용하여 동시성을 제어합니다.
*   **주문 순서**:
    1.  레버리지 및 격리(Isolated) 마진 설정.
    2.  시장가 진입(Market Order) 실행.
    3.  동시에, 반대 포지션으로 **스탑 마켓(Stop Market) 주문** 발동. (LLM이 지정한 손절가와 Risk Gate의 강제 2% 손절 중 더 타이트한 쪽을 선택)
*   **시뮬레이션 모드**: API Key가 없거나 SIM 모드일 경우 가상의 거래 ID를 생성하고 슬리피지(2~8 bps)를 고려한 시뮬레이션 진입을 처리합니다.

## 3. 복구 로직 (Position Recovery)
서버가 재시작 되거나 크래시가 났을 때:
*   DB에 `OPEN`으로 기록된 포지션을 읽어옵니다.
*   실제 바이낸스 거래소와 통신(`_syncPositions`)하여 포지션이 살아있는지 확인하고 메모리에 복구합니다.
*   만약 거래소에서는 청산되었는데 DB에만 남아있는 고아(Orphan) 포지션이라면 DB 상태를 `CLOSED`로 동기화합니다.
